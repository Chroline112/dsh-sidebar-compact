# 侧边栏精简 / Compact Sidebar

## Public installation

In DSH's Add Plugin dialog, select the official npm registry and enter:

```text
dsh-sidebar-compact
```

GitHub source: https://github.com/Chroline112/dsh-sidebar-compact


版本：`1.3.2`。面向 DSH `0.2.1-rc.2` / `0.2.1-rc.3` 的原生侧边栏，按宿主实际提供的插槽选择菜单实现。当前机器为 rc.2；rc.3 分支通过接口模拟验证，尚未在另一台电脑或其他操作系统上实测。

## 在其他电脑安装

1. 将 `dsh-sidebar-compact-1.3.2.tgz` 复制到目标电脑的固定目录。它是完整 npm 安装包，直接安装，无需解压或复制本机的 node_modules。
2. 在目标电脑的 DSH 中，让助手使用插件管理工具安装该文件的完整本地路径。例如：「安装本地插件 D:/Downloads/dsh-sidebar-compact-1.3.2.tgz」。macOS / Linux 使用对应的绝对路径。
3. 已装旧版时按插件管理工具的升级提示操作；若提示包已存在，先通过插件管理卸载旧包，再安装新包。
4. 根据安装结果刷新页面或重启 DSH，进入「插件 → 侧边栏精简」逐项开启需要的功能。

包内没有本机绝对路径、外部运行依赖、系统专用二进制或安装脚本。日常安装和使用不需要另装 Python 或执行构建。设置保存在目标浏览器；安装包不携带原电脑的设置，新电脑默认全部关闭。同一浏览器升级会保留此前明确保存的偏好。

## 按需开启

进入「插件 → 侧边栏精简」详情页设置。所有侧边栏调整默认关闭，避免安装后直接覆盖其他主题的导航、间距或控件。每项独立保存，已加载新版后切换立即生效。

| 开关 | 开启后的效果 | 默认 |
| --- | --- | --- |
| 精简面板导航 | 将插件市场以外的面板移入“更多” | 关闭 |
| 覆盖项目间距 | 应用下方项目间距档位 | 关闭 |
| 覆盖会话密度 | 应用下方会话字号、行高和间距档位 | 关闭 |
| 点击工作区标题收起全部 | 点击工作区标题收起所有项目会话；平铺视图除外 | 关闭 |
| 隐藏新版本按钮 | 隐藏侧边栏更新入口，宿主继续管理检查与安装 | 关闭 |

关闭对应开关时撤下插件样式或控件，恢复宿主和主题的显示。精简导航不会修改宿主的面板固定偏好。

## 列表档位

项目间距与会话密度各有「标准 / 适中 / 紧凑」三个档位，默认「标准」。对应覆盖开关关闭时档位控件禁用，保留已选值；重新开启后应用该值。「标准」不添加覆盖。

| 设置 | 标准 | 适中 | 紧凑 |
| --- | --- | --- | --- |
| 项目行高 | 跟随主题 | 28px | 26px |
| 相邻项目分组间距 | 跟随主题 | 1px | 0px |
| 会话行高 | 跟随主题 | 28px | 26px |
| 会话标题字号 / 行高 | 跟随主题 | 13px / 20px | 13px / 18px |
| 相邻会话间距 | 跟随主题 | 0px | 0px |

覆盖限定在原生 `sidebar.workspaces` 插槽。CSS 匹配完整本地类名后缀，不依赖构建哈希。宿主未来更改类名或插槽结构时仍需重新核对。

## 升级与设置保存

设置保存在当前浏览器的 localStorage。沿用以下旧键，保留此前明确保存的收起操作、更新入口和密度档位：

- `dsh.sidebar-compact.collapse-workspaces.v1`
- `dsh.sidebar-compact.show-update.v1`（界面使用反向的“隐藏”开关）
- `dsh.sidebar-compact.project-spacing.v1`
- `dsh.sidebar-compact.session-density.v1`

新增开关键均默认关闭，旧密度档位也需手动开启覆盖后才应用：

- `dsh.sidebar-compact.navigation.v1`
- `dsh.sidebar-compact.project-enabled.v1`
- `dsh.sidebar-compact.session-enabled.v1`

包名为 `dsh-sidebar-compact`，Loader 条目为 `sidebar-compact`。没有外部运行依赖、安装脚本或额外构建步骤。rc.2 使用插件提供的“更多”菜单，宿主存在原生更多菜单时沿用对应插槽。标题收起按钮与旧版菜单使用 CSS Anchor Positioning；缺少该能力时使用侧边栏底部入口。

精简导航关闭时不会读取主题的面板接口，也不会注册导航样式与“更多”菜单。开启时如主题未提供原生面板接口，仅跳过导航功能并在控制台提示，其他开关仍独立工作。关闭导航会立即撤下该功能的注册；停用插件会清理插件样式、菜单、控件与监听。

CSS `:has()` 的包装层选择器独立置于能力检查中，避免旧浏览器连带忽略普通按钮规则。标题收起按钮与旧版“更多”菜单仅在浏览器支持所需的完整 Anchor Positioning 属性时定位，否则保留底部入口。主题替换原生结构后，基于原生类名的间距或更新按钮覆盖可能不匹配；需要相应主题实际保留原生插槽和结构。

安装后以插件管理返回的加载状态为准。若提示需要重启，重新启动 DSH 后加载新版。

## 验证

开发者可在包目录运行 `npm test`（需要 Node.js，验证脚本仅使用内置模块）。验证覆盖清单、双语资源、九种密度组合、默认开关、旧设置读取、偏好通知、独立渲染门控、旧版与新版导航注册/撤下/重启用、主题缺少原生接口和 CSS 能力检查。验证脚本从自身所在目录读取文件，可随安装包换目录运行。发布时还对实际 tgz 解包后的副本运行同一验证。此类检查不等同于桌面 UI 点击与布局实测。
